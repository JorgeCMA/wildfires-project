# Audit 03d/03e — pre/post-execution review (2026-10-16)

**Scope**: `notebooks/03d_eventos.ipynb`, `notebooks/03e_validacion.ipynb`, and their
outputs under `data/processed/unsupervised/`. Read-only audit (no execution; all
numbers verified by recomputation with seed 42, `.venv/Scripts/python.exe`).

**Bottom line**: both notebooks are *computationally faithful* — every output CSV on
disk reproduces bit-for-bit from the notebook code. The issues are in markdown claims
vs. gating logic and in the project-wide positional-join fragility, not in the math.

## 1. 03d_eventos — mostly clean

  with **EPSG:3035** (plan correction: UTM 30N doesn't cover Canarias; recorded in

  plan's **[DECIDED]** items. Raw units, no scaler (hard rule 4.3 ✓). DBSCAN is
  deterministic, no seed needed.
- `eventos.csv` reproduces exactly on recomputation (`fit_dbscan_events(eps=10)`):
  23,142 rows × 1 col (`event_id`); **1,177 events + 4,943 noise rows (21.4%)**.
- `eventos_resumen.csv` (1,177×19) matches the plan's output contract
  (`event_id, n, first_day, last_day, duration_days, x/y_centroid_km, x/y_span_km,
  ccaa_top, ccaa_n, frp_max, PC1_mean…PC7_mean`); Σ n = 18,179 = non-noise rows;

- eps sweep {5,10,15,20} km → events {1439,1177,1139,1124}, noise {0.255,0.214,0.199,
  0.172} — the claimed "stable zone" and EPS=10 are consistent with the data.

- Cross-references verified: vs 03b (`kmeans_a_k5`, distinct regimes per event
  {1:836, 2:272, 3:60, 4:8, 5:1}, multi-regime fraction **0.290**); vs 03c

  {(0,1]:0.0042, (1,3]:0.0079, (3,7]:0.0010, (7,400]:0.0101}). Noise CLC top-5

  Castilla-La Mancha:582, Extremadura:525, Castilla y León:387, C. Valenciana:379}
  match recorded outputs exactly.

### Problems

1. **eps hand-picked, not knee-derived.** Plan says "chosen from the k-distance knee
   (plot shipped as a figure)". Notebook sweeps {5,10,15,20}, asserts EPS=10
   ("rodilla aproximada"); no knee-finding method, k-distance figure inline-only.
   Defensible (count/noise plateau), not objective.
2. **Positional-join fragility is live.** `eventos.csv` carries only `event_id` — no
   key column, no saved index. The "common index with the features CSVs" is row order,

3. Minor: unused `EVENT_MATRIX_COLS` import (cell 1); sensitivity/sweep tables are

## 2. 03e_validacion — faithful numbers, two substantive holes

### Confirmed correct

- All **27 rows of `validacion_resumen.csv` reproduce exactly**: resample ARI
  (k5 0.465 / k7 0.709 / k12 0.946), spatial min profile-corr (0.107/0.248/0.822),
  temporal corr (0.471/0.570/0.683), std-vs-robust ARI (0.450/0.440/0.605), severity
  max |δ| (0.714 / 0.847 / 0.863), non-coincidence max ARI (0.138/0.151/0.172),
  NMI max (0.183/0.211/0.257), GMM overlap (0.051/0.054/0.058). Controls: month
  max|δ|=0.401, ccaa 0.699.
- `perfiles_tipologia.csv` (12 groups × 7 cols) matches a fresh k12 refit exactly
  (max abs diff 0.0). Verdict logic sound: k5/k7 rejected, **k12 accepted**,
  lowest-k-among-accepted.
- Scaler discipline correct everywhere (fold-internal fits; no `normalized.csv` reuse);
  no target leakage (`frp` used only as §7B outcome); GMM posteriors rows-sum-to-1
  enforced; anchor math correct (best control 0.699 → `recommended_bar` 0.70).

### Problems

1. **Stale config narrative (highest priority).** Cells 18/19 still frame the Cliff's-δ
   bar as "0,2 provisional", but `configs/project.yaml` `unsupervised.min_cliff_delta`
   is actually **0.7** after the anchoring the plan anticipated. And **k5's severity
   pass is a knife-edge: 0.714 vs 0.7 (0.014 margin), barely above the CCAA control
   (0.699)** — the notebook never discusses how fragile the k5 shortlist is.
2. **Spatial-stability gate is vacuous.** `ok = (groups_found == k).all()` can never
   be False — KMeans always returns exactly k clusters. k5 "passes" spatial stability
   with profile correlation **0.107** (reported as `valor`/`min` but **not gated**).
   The plan's acceptance rule ("no group disappears without a dominant region") is
   effectively unchecked.
3. **`solape_gmm` hardcoded `pasa: True`** — reported, never gated; can never
   influence the verdict (consistent with the "information only" framing, but worth
   an explicit note).
4. **Positional-join fragility**, same as 03d: no shared id column anywhere; only
   `len` asserts. An upstream re-sort silently corrupts every check.
5. **Physical-sense proxy thinner than advertised**: gate tests only VPD–RH (<0) and
   VPD–ET0 (>0); markdown mentions wind/precipitation, which play no role in the gate.
6. Minor: `pairwise_ari` off-diagonal extraction (`m.where(~eye).min().min()`) is
   correct for the 2×2 case but silently wrong if extended to >2 variants.
7. Out of scope but noted: 03e never reads `anomalias_*` / `eventos*`; cell 20 promotes
   `score_anomalia`/`cluster_meteo` as model candidates without any validation gate
   on them. Fine if §7 covers only the typology — say so explicitly.
